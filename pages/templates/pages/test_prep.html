My method

How I reverse-engineered the SHSAT and Hunter.

Most test prep platforms generate questions with AI or write them from intuition about what "looks like" the real test. I did something different. I took the official DOE handbooks and Hunter sample materials apart, ran statistical and linguistic analysis on the real items, and used the results to write every practice question by hand.

01 — The corpus

Start with what the test makers actually published.

The DOE publishes sample tests and answer rationales for the SHSAT. Hunter publishes sample items for each section. These are not study guides written by third parties. They are the test maker's own items, with the test maker's own explanations for why each wrong answer is wrong. That is the corpus. Everything I build starts there.

02 — Analysis

What makes a wrong answer attractive?

I read every answer rationale the DOE published and categorized the reasoning errors behind each wrong answer. Not "this is wrong because it contradicts the passage" but the specific cognitive move that makes a student pick it: surface-level word matching, extreme language that sounds authoritative, a causal claim that reverses cause and effect, a conclusion that is true but answers a different question.

The SHSAT ELA alone has 13 distinct reading comprehension trap types and 12 editing trap types. Each one exploits a different failure in how a student reads or reasons. Math has its own set: sign errors, unit confusion, off-by-one miscounts, and several cognitive traps like anchoring on the first plausible number or confusing a rate with a total.

03 — Construction

Build questions that hit the same traps.

Every question on this platform is written by hand, not generated. The wrong answers are deliberate: each one is tagged with the specific trap type it represents, so the question does not just test whether a student knows the answer. It tests whether they can resist the particular misread that the real exam exploits.

Questions are constructed according to latent variable theory and factor analysis, which means they are designed to measure the same underlying skills that the real test measures. A practice question that is "hard" for the wrong reasons teaches nothing. A practice question that is hard because it contains the same cognitive trap as the real item teaches the student exactly what they need to learn.

04 — Error analysis

Every wrong answer has a name.

After each test, the platform does not just show a score. It shows which trap types caught your child and how often. If a student keeps falling for "true but irrelevant" distractors in reading comprehension, that is a specific, trainable problem. If they keep making sign errors in algebra, that is a different problem with a different fix.

The error analysis breaks down accuracy by skill area, shows time per question, tracks which mistake patterns persist across multiple tests, and projects school placement against real cutoff scores. A parent should never have to guess where the problem is.

05 — No AI feedback

Every explanation was written by a person.

Many test prep platforms use language models to generate explanations on the fly. I do not. Every explanation your child sees after a wrong answer was written, reviewed, and structured by me. There is no chatbot interpolating between training data and calling it feedback. When the explanation says "this answer is wrong because it confuses correlation with cause," that sentence was written because I looked at the question, identified the trap, and wrote the explanation to address it directly.
